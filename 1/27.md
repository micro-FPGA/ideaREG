## Idea

### Title

**FPGAinFPGA** — implementing an emulated FPGA architecture inside a real FPGA, allowing the emulated fabric to be reconfigured through memory writes without reprogramming the host FPGA.

### Description

FPGAinFPGA is the concept of using a host FPGA's logic resources to emulate a smaller FPGA fabric. The host FPGA is programmed once with the FPGAinFPGA implementation. The emulated FPGA's behaviour is then determined by a configuration bitstream that the host FPGA reads from its memory at runtime. Changing the emulated FPGA's behaviour requires updating the configuration memory, not reprogramming the host FPGA itself.

The emulated FPGA can be a model of a specific commercial FPGA family, a custom FPGA architecture designed specifically for the emulation, or a simplified pedagogical FPGA suitable for teaching. The choice of emulated architecture depends on the application — different use cases benefit from different emulated architectures.

**Use cases for FPGAinFPGA:**

**Dynamic reconfiguration without full FPGA reprogramming.** Many FPGA platforms have slow or limited reconfiguration capabilities. The emulated FPGA inside a host FPGA can be reconfigured rapidly through memory writes, providing reconfiguration speeds that the host FPGA's native reconfiguration may not match.

**Partial reconfiguration on platforms that lack hardware support for it.** Some FPGAs do not have hardware partial reconfiguration. FPGAinFPGA can provide this capability at the cost of fabric efficiency. Engineers willing to accept the overhead gain the partial reconfiguration capability on platforms that would not otherwise support it.

**Custom FPGA architectures for specialised applications.** Engineers can design FPGA architectures optimised for specific application domains and implement them as FPGAinFPGA cores. The custom architecture can have characteristics — logic block organisation, routing topology, embedded resources, configuration interface — that commercial FPGAs do not provide.

**Security and isolation.** The emulated FPGA can be sandboxed from the host FPGA, providing isolation guarantees that the host platform may not natively provide. Bitstreams loaded into the emulated FPGA cannot directly access the host FPGA's resources outside of the controlled emulation interface. This matters for applications where untrusted bitstreams need to be loaded safely.

**Educational visibility.** The FPGAinFPGA implementation makes FPGA architecture concretely visible. Students studying FPGA design can examine and modify the emulated fabric's source code, which is not possible with commercial FPGA silicon. The implementation becomes a teaching tool.

**Research platform.** Academic and industrial researchers studying FPGA architectures can use FPGAinFPGA as a platform for experimenting with novel architectural ideas without needing to fabricate custom silicon. The research cycle becomes shorter and cheaper than alternatives requiring custom ASIC fabrication.

### The concept's history and current status

FPGAinFPGA is not a new idea. Multiple independent articulations exist:

**The deleted OpenCores project.** A project on OpenCores existed at some point that implemented an FPGAinFPGA concept. The project has been deleted from OpenCores and the source code is no longer accessible through that platform. Whether the source survives anywhere else is unknown to the registrant.
