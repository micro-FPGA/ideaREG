## Thesis

A MOTUPER is defined by its **link**, not by its processor.

The Transputer's lasting idea was that the link was the standard: anything that
spoke it could join. MOTUPER takes that literally. Any device that speaks the
link is a node — an FPGA module, a retired phone, an old PC, a future chip.

## Three rules

1. **Nothing moves but messages.** No shared memory, no global address space.
   Data and weights stay where they are placed; only messages travel between
   nodes, in the CSP / occam tradition of the Transputer.
2. **The program is a process network.** A model or application is compiled
   into a graph of processes, each placed on a node and connected by channels.
3. **Every node is its own root of trust.** Each node holds a public key and
   refuses any slice of code or weights that is not signed. There is no single
   bootloader to compromise; the signature check happens at every node before
   control passes.

## Parts

- **Node** — local memory, some compute, two or more links, and a key.
  Nodes may be heterogeneous.
- **Link** — point-to-point serial channel with framed messages and
  credit-based flow control. Independent of the physical layer: USB,
  Ethernet or LVDS.
- **Switch** — an FPGA that routes link traffic between nodes, in the role
  the Inmos C004 link switch played for Transputers. It keeps the host PC
  out of the data path, avoiding the double hop through the host in
  [ideaREG #32](https://github.com/micro-FPGA/ideaREG/blob/main/1/32.md).
- **Loader** — discovers the nodes, places the process graph on them,
  balancing by memory and link bandwidth, and sends each node its signed
  slice.

## Worked example

Twenty retired phones with about 8 GB each hold a model of roughly 70 billion
parameters quantised to 4 bits (about 40 GB). The model is split by layers;
only activations of a few kilobytes per token cross the links.

- **Links:** about 1.5 ms per hop, roughly 30 ms per token across twenty
  nodes. Not the bottleneck.
- **Memory:** each node streams its ~2 GB slice per token, and the stages run
  in sequence. A single user gets roughly 0.5–1 token per second.
- **With twenty requests in flight**, every node is busy and aggregate
  throughput approaches twenty times the single-user rate.

A large model on hardware that already exists, with no lead time: slow for one
user, respectable for many.

## Prior art, and what might be new

Distributed inference across ordinary devices already exists (exo,
llama.cpp's RPC backend, Petals). Wafer-scale meshes such as Cerebras and
Tenstorrent already keep weights resident and pass messages.

The claim is the combination: the link as the definition of the machine;
recycled, heterogeneous nodes; an FPGA link switch; and signature
verification at every node.

## Known limits

- Single-stream speed is bounded by one node's memory bandwidth.
- Splitting individual layers across nodes is impractical over slow links.
- Heterogeneous nodes are hard to balance.
- Phones throttle under sustained load, and many lithium cells held at full
  charge in one enclosure are a fire hazard.
- The loader is the hard software, and it is unwritten.

## On the name

MOTUPER is an exact anagram of COMPUTER with the C removed. C is carbon.
Wordplay only — nothing is claimed by it.
